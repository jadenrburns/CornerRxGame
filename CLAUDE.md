# Corner Rx (pharmacy tycoon study game)

`index.html` is the deployed game (GitHub Pages). It is **generated** from the files in `src/`. Edit `src/`, never `index.html`.

## Build and ship
1. Bump `GAME_VERSION` in `src/game.js`.
2. `cd src && sh build.sh && node --check game.full.js` (builds `src/corner-rx.html`).
3. Run the tests from `src/` (see below).
4. `cp src/corner-rx.html ../index.html` and commit both `src/` and `index.html`.

`build.sh` concatenates, in order: `head.html`, the three.js r128 CDN tag, then `net.js bank.js pt3*.js pt4.js cycle.js mol.js mc3.js micdata.js th3.js th3c.js ger.js th553.js him.js lab.js ind.js drugs.js shop.js gear.js deck.js crowd.js world.js game.full.js` into one page. `ext.js` is spliced into `game.js` at the `/*@EXT@*/` marker, and `mic.js` at `/*@MIC@*/`, to make `game.full.js` (never write those marker strings inside a comment in the spliced files). Add new question files to the list in `build.sh`.

## Files
- Questions: `Q(category, difficulty 1-3, question, correct, [3 wrongs], explanation, section)` in `bank.js`. Category files: `pt3*.js`, `pt4.js` (PharmTox), `th3.js` (Therapeutics Exam 3), `th3c.js` (contraceptives), `th553.js` (`T553`), `him.js` (`HIM`, Andy's heart failure questions), `lab.js`, `ind.js`. Weekly drug questions are generated from `drugs.js`.
- Categories are listed in `CATS` near the top of `game.js` (also `FLAVOR`). A new category also needs a slot in `COURSES` (which course card it sits in) and a chip label in `CHIP`; see "Topics menu".
- `world.js`: the 3D pharmacy (three.js) with patients, queue, sky events, Andy. `crowd.js`: movement and collisions. `ext.js`: events (visitors, inspector, driver), Andy game logic, blessing buff. `game.js`: everything else (cards, menus, saves, awards).
- Dev mode: add `?dev=1` to the URL for the "Test:" buttons (events, Andy walk / ascension / angel flyover / smash).

## Shop
`shop.js` holds the shop item lists (wall paint, floors, technician uniforms with buffs, decorations). Pharmacist hairstyles and cyborg parts moved to `gear.js` (the `SHOP_HAIR` / `SHOP_CYBER` arrays in `shop.js` are no longer read). Purchases are saved in `S.store` (`own` ids, equipped `walls`, `floor`, `uni`, `deco`). The UI is the Shop tab on the Character screen (`shopHTML`, `shopBuy`, `shopUse` in `game.js`); sections are `<details class="crs" data-shop>` accordions (open state in `shopOpen`), no chips. `world.js` draws it: `api.setStore` (walls, floor, decorations), `api.setStaffLook` (uniforms), cyborg parts in `buildCosm`/the arm loop, hair styles 12 and 13. Uniform buffs: `uniBuff()` feeds `techRate` and `buffPay`, and only applies with at least one technician. Never rename a shipped item id. Prices and buffs are placeholders; tune them in `shop.js`. Test: `te41`.

## Power-ups, daily goals, recall and regulars
- Power-ups (`PW` in `game.js`): hint pill, second chance, reference binder. Counts in `S.pw`, bought in the Shop tab ("Power-ups", `shopBuy` kind `pow`), used from the buttons under each question. The old Reference Library upgrade is gone; saves are migrated in `load()` (cost refunded, `hintsLeft` becomes `pw.hint`). Its wall space on the left is now the mastery shelf.
- Daily goals (`ext.js`, `DG`, `dailyState`, `dailyTick`): three goals per local day, seeded by date, stored in `S.daily`. Menu entry "Daily goals" opens view `daily`.
- Recall patients (`S.recall`): a missed question returns about a day later with the same seed/body (same look). Regulars (`S.reg`): mastering a whole week unlocks one, who asks questions from that week. Both are rolled by `specialRoll` (passed to `World.init`), ignore topic filters on purpose, and the card shows a purple (recall) or gold (regular) banner (`spBanner`). `World.setMastery(list)` draws one jar per regular on the left-wall mastery shelf.
- Dev (`?dev=1`): "Test: recall patient", "Test: regular patient". Tests: `te44` (power-ups), `te45` (daily goals), `te46` (recall and regulars).
- CSS goes inside the `<style>` block in `head.html`, above `</style>`. Anything appended after the markup is not applied.

## Therapeutics Exam 3 categories and draw questions
- Exam 3 is split into three categories (chips in the Therapeutics course card): `TH3F` (IBS, constipation, diarrhea, including opioid-induced constipation), `TH3C` (contraceptives, `th3c.js`) and `TH3` (everything else: IBD, ulcers, hemorrhoids, GI tests, bowel prep). `th3.js`'s `T()` picks `TH3F` or `TH3` from the section name; `th3c.js` uses `CT()`. `load()` copies a switched-off `TH3` to the two new chips.
- Draw questions: `CTDRAW(hormone, ...)` in `th3c.js` adds `q.draw` (`FSH`, `LH`, `E2`, `P4`). The card shows a blank 28-day graph (`cycle.js`, `cycSVG`) and the player drags a line; `cycScore` compares shape (smoothed, min-max scaled, correlation and mean error, plus peak day) with curves traced from the instructor's worksheet. `drawHTML` and the pointer handlers are in `game.js`; they skip the confidence prompt, hint pill, second chance and binder. The text answer (`a`) describes the curve so review lists still read. Tests: `te50`.

## Geriatrics
`ger.js` (`GQ(section, d, q, a, w, e, slide)`, category `GER`, chip "Geriatrics: aging, polypharmacy, deprescribing" in the Therapeutics course card) holds 99 questions from the PHAR 451 Geriatric Pharmacotherapy handout, each citing the handout slide number. Test: `te51`.

## Quizlet import
My studies has an "Import from Quizlet" box (`addQuizlet`, `quizletToJson` in `deck.js`). Players paste Quizlet's Export text (term, tab, definition); it becomes a normal deck of multiple-choice cards (wrong answers filled from other cards, so 4+ cards). Direction toggle: term to definition or definition to term. An optional https://quizlet.com/ link is saved as `deck.url` and shows an "Open Quizlet" button. Quizlet has no public API and blocks browser fetches, so the game never reads the link. Test: `te49`.

## Study sources
`Q(...)` takes an optional 8th argument `s`, a short source like `IBD lecture, slides 33, 36`. It shows as "Study source" under the explanation. `th3.js`'s `T(section, d, q, a, w, e, s)` passes it through. When adding questions from a lecture deck, cite the slide numbers. The extracted slide text is not stored in the repo; ask the user to attach the deck again.

## Tests
Node + Playwright, run from `src/`: `node te38.js` etc. They load `corner-rx.html` with `three-stub2.js` standing in for three.js (so the 3D logic runs but nothing is drawn). Useful ones: `te19`, `te26`, `te28`, `te54` (Topics menu), `te38` (Andy events), `te39` (weekly quiz achievements). `te35` and `te37` tested the old P1/P2/P3 folder tabs and were removed in v120. ## Conventions
- Wrong answers must not be arguably correct (for example an indication shared with the right drug). Keep the correct answer from being the longest option every time. Audited in v115: across the hand-written bank the correct answer is the longest option in about 31% of questions (was 49%). Check the share per category after adding questions (count questions where the correct answer is strictly longer than every wrong one) and keep each category roughly 25 to 40%. Fix by lengthening plausible wrong answers, not by padding the correct one. Do not push a category to 0%, that is also a tell.
- Questions use plain language; no em dashes.
- 3D can be checked visually in the build environment: the user attaches `three.min.js` (r128, from cdnjs), then run `THREE_JS=/path/three.min.js SHOT_DIR=/some/dir node shot3d.js <dir-arg> dev-him-asc 12 900` from `src/` (args: ignored, dev button id, frame count, ms between frames; the first arg is only the scratchpad fallback path). It uses headless Chromium with SwiftShader. The sandbox cannot download three.js itself. Still confirm by playing with `?dev=1`.
- Saves live in the browser (`localStorage`); keep save-format changes backward compatible.

## Confidence and SM-2 review
- After picking an answer the card shows "How sure are you?" (Guess / Pretty sure / Certain, keys 1 to 3) before the result. `answer(idx, conf)` in `game.js` gates on `confNeeded()` (skipped for generated calc, Karen, Jim, elder, lab, callers, events, visitors, and when `S.set.conf === false`). `cur.pend` holds the pending pick; `confBar()` draws the buttons.
- `ext.js` has the SM-2 code: `srGrade` (grade 0 to 5 from correctness and confidence), `srUpdate` (fields on `S.mastery[k]`: `n` reps, `d` interval days, `ef` ease, `due` timestamp, `cw` certain-but-wrong flag, `gr` consecutive guess-rights), `srSeed` (starts older saves from their box), `reviewDue` (uses `due`, falls back to the old `iv`/`t` ladder), `calibNote` (accuracy by confidence, `S.cf`). The old Leitner `box` still drives mastery (>= 2); a guess-right does not raise it unless it happens twice in a row.
- Modes (`MODES`): Smart mix (`mixed`) and Individual review (`review`) use the confidence prompt and SM-2 (`srOn()`); Review misses and New only do not. The old Even shuffle / Linear mode (`even`) was removed, and `load()` moves saves that still have it to Smart mix. Individual review serves only `srDue` questions from every topic (ignores topic filters, no calc), shows a "Nothing due" card when empty, and `dueCount()` feeds the chip and the progress note. The prompt is skipped when the question was already answered today (`askedToday`, `m.lt`), so same-day repeats are quick practice; the first look and later reviews still ask. Smart mix weights `cw` questions up. An extra right answer before the review date (`m.due` in the future) does not lengthen the interval (found by the mode simulation); a wrong one still resets it. Tests: `te47`, `te48`. Other tests load `corner-rx.html?noconf=1` to skip the prompt.

## Background tabs
Hidden tabs throttle `setInterval` and pause `requestAnimationFrame`. Use real elapsed time (`tickDt` in the 250ms loop in `game.js`), never a fixed per-tick amount, for income and countdowns. `world.js` runs exactly one render loop through `startLoop()` (it cancels the pending frame); starting a second chain after a hide/show doubled the game speed (v117). Test: `te52`.

## Therapeutics content rule
Do not write Therapeutics questions about study results or how often something occurs (population percentages, trial findings, incidence, typical-use failure rates). Thresholds, doses, goals, definitions and mechanisms are fine. The v118 pass removed 28 such questions (8 contraceptive, 20 geriatrics) and stripped incidence percentages from three answers. The event character is now named Andy (ids and categories such as `HIM` keep their old names).

## Symptom duration questions
Any question about how many days or weeks symptoms last, or how long to self-treat before referral, must name the disease state in the question text itself (for example "minor hemorrhoid symptoms", not "minor symptoms"), and must not lean on "the same patient" from another card. Test: `te53` flags Therapeutics questions that mention a time span plus symptoms or referral but no disease word. Add new disease words to its list when a new topic needs one.

## Online: question flags and leaderboard (v123)
No login. `src/net.js` holds `RX_NET = { url, key }` (a Supabase project URL and its anon public key, both safe to publish) and a tiny fetch wrapper `Net` (`on`, `rpc`, `weekKey`, `uuid`). Empty values keep everything offline: the Leaderboard menu button hides and the flag link falls back to the old GitHub issue link. `localStorage.rxNet` ({"url","key"}) overrides it for testing.
- Backend is `src/net/supabase.sql` (run once in the Supabase SQL editor after setting the admin key line). Tables have row level security and no policies; the game only calls functions: `submit_flag`, `push_score`, `leave_board`, `get_board`, and admin-only `admin_flags`, `resolve_flag`, `admin_remove_player`. A leaderboard row is owned by a secret token (`S.tok`, travels in the save code); `S.pid` is the public row id. Tested against a local Postgres in v123.
- Flags: after answering, "Flag this question" opens a small form (reason + note) that calls `submit_flag`. The result card is cached in `cur.resHTML`, so the flag area is a `<!--FLAG-->` marker filled at render time by `flagLink`. The author reads them live (8 s poll) by opening the game with `?flags=1` (or the dev menu entry) and saving the admin key once; Resolve/Reopen use `resolve_flag`.
- Leaderboard (v126): menu > Leaderboard, ranked by total money made (`S.earned`, lifetime, never lowered by spending or retiring). Opt in with a nickname (`S.nick`, `S.boardOn`); shares only the nickname and `earned`, pushed 45 s after a correct answer via `push_score(p_pid, p_tok, p_name, p_earned, p_v)`; `get_board()` returns the top 100. The server clamps the value and only lets it go up; there is no other cheat protection. `net/supabase.sql` is idempotent and also upgrades a project made with the older weekly/mastery version (adds `earned`, replaces the two functions); old columns stay unused.
- Welcome prompt (v124): `maybeJoinAsk` shows a one-time "Join the leaderboard?" nickname dialog (`.joinask`) once the tutorial is done, only when `Net.on()` and the player is not on the board (`S.boardAsked` remembers a skip). Test: `te57`. Tests that run online should seed `boardAsked: true`.
- v125: `RX_NET` is filled in (Supabase project `crzgekhluqnyzeuhffib`, publishable key; `sb_publishable_` keys go in the `apikey` header only). The sandbox cannot reach Supabase, so live behaviour is checked only by the user. Tests: `localStorage.rxNet = {"off":1}` forces offline; the join prompt stays quiet under automation (`navigator.webdriver`) unless the URL has `?ask=1`.
- The claude.ai artifact cannot reach the database (sandbox blocks outside requests). Online parts work on the real site only. Test: `te56` (fake backend that mimics the SQL).
